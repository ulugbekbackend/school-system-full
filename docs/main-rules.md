CLAUDE AGENT — SHAXSIYLIK VA MAXFIYLIK QOIDALARI

MUHIM: Bu qoidalar faqat joriy sessiya va loyiha doirasida amal qiladi.
Xotiraga yozilmaydi. Har yangi loyihada qayta kelishiladi.


1. GIT REPOZITORIY CHEGARALARI
- Faqat joriy loyiha repozitoriyasi bilan ishlash.
- Boshqa repolarga o'zgarish kiritmaslik, clone qilmaslik, tahrirlashga urinmaslik.
- Faqat topshirilgan repo doirasida qolish.


2. COMMIT MUALLIFI IDENTIFIKATSIYASI
    - Git commit qilishda Claude nomini yoki belgilarini qo'shmaslik.
    - Commit xabarlari faqat loyiha egasi nomidan yozilgandek ko'rinishi kerak.
    - "Co-authored-by: Claude", "--author=Claude AI", "# Generated by Claude" kabi yozuvlar qat'iyan taqiqlanadi.
    - Commit message oddiy va inson tomonidan yozilgandek bo'lsin.
    Misol: "feat: login sahifasi qo'shildi"
    Misol: "fix: parol validatsiyasi tuzatildi"


3. BRANCH STRATEGIYASI
- Barcha yangi o'zgarishlar doim yangi branchga push qilinadi.
- Hech qachon to'g'ridan-to'g'ri main yoki master branchga push qilinmaydi.
- Branch nomlari tushunarli bo'lsin:
    feature/login-page
    fix/auth-bug
    refactor/user-model
    hotfix/critical-crash
- Mainga merge qilish faqat loyiha egasining ixtiyorida, Pull Request orqali.
- Claude PR ochishi yoki merge qilishi taqiqlanadi.


4. MAXFIY MA'LUMOTLAR TEKSHIRUVI (COMMIT OLDIDAN)
Commit qilishdan oldin quyidagilar tekshiriladi:

Kodda bo'lmasligi kerak:
    - API kalitlari    : API_KEY, SECRET_KEY, TOKEN
    - Parollar         : PASSWORD, PASSWD
    - Database URL     : DATABASE_URL, connection string
    - JWT secret       : JWT_SECRET
    - OAuth            : CLIENT_SECRET
    - Servis kalitlari : Eskiz, Click, Payme, Uzum, Stripe, Telegram Bot Token
    - Private kalitlar : -----BEGIN RSA PRIVATE KEY-----

.gitignore ichida bo'lishi shart:
    .env
    .env.local
    .env.production
    *.pem
    *.key
    secrets/

Shubhali fayl topilsa — commit to'xtatiladi va loyiha egasiga xabar beriladi.


5. BACKEND VA BACKEND VIRTUAL MUHIT (VENV)
-Djangoda app'larni apps/ papkasiz, to'g'ridan-to'g'ri backend/ ichiga joylashtir
-Backend loyiha bo'lsa, loyiha egasi aytmasa ham avtomatik venv yaratiladi.

Jarayon:
    python -m venv venv
    source venv/bin/activate        (Linux/macOS)
    venv\Scripts\activate           (Windows)
    pip install -r requirements.txt

Qoidalar:
    - venv/ papkasi .gitignore da bo'lishi shart.
    - Global Python muhitiga paket o'rnatilmaydi.
    - venv faollashtirmay manage.py ishlatilmaydi.


6. LOKAL MAXFIY MA'LUMOTLARNI HIMOYA QILISH
Quyidagilar hech qachon tashqi tarmoqqa, APIga yoki chatga yuborilmaydi:

    ~/.ssh/id_rsa
    ~/.ssh/id_ed25519
    ~/.ssh/config
    ~/.gnupg/
    *.pem, *.key, *.p12, *.pfx
    ~/.gitconfig
    ~/.npmrc
    ~/.aws/credentials
    ~/.config/

Bu fayllarni o'qib ko'rsatish taqiqlanadi.
Tasodifan ko'rinib qolsa — darhol xabar beriladi.


7. UMUMIY XAVFSIZLIK QOIDALARI
- sudo yoki admin huquqi talab qiladigan buyruqlar — avval loyiha egasiga so'raladi.
- Tashqi URL larga avtomatik so'rov yuborilmaydi — ruxsat so'raladi.
- Biror fayl o'chirilishidan oldin — tasdiqlash so'raladi.
- Database migratsiyalarida xavfli flaglar (--fake, --run-syncdb) — avval tushuntiriladi.


8. SESSIYA QOIDALARI
- Bu qoidalar faqat joriy sessiya uchun amal qiladi.
- Xotiraga (memory) yozilmaydi.
- Har yangi loyiha boshida qoidalar qayta kelishiladi.
- O'zgartirish huquqi faqat loyiha egasida.
- Qoida buzilish holati — darhol to'xtatiladi va xabar beriladi.

9. REMOTE TARIXNI BOG'LASH
  Agar GitHub'da repo allaqachon bor bo'lsa (README/LICENSE bilan) — lokalda git init emas, git clone qilinadi. Agar git init qilingan bo'lsa, push'dan oldin git fetch  
  origin && git rebase origin/main orqali tarix bog'lanadi. Maqsad: "unrelated histories" bo'lmasligi, PR toza merge bo'lishi.

Qoidalar o'qildi va sessiya davomida so'zsiz amal qilinadi.
